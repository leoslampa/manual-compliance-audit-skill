# 说明书审核 Skill 说明书

> **技能名称**：说明书审核（说明书多法域合规审核）
> **版本**：v1.0（2026-08-07）
> **适用产品**：消费电子说明书（儿童电话手表等）多法域合规审核
> **定位**：将"说明书合规审核"从人工经验固化为可复用的分级审核体系，产出可执行的整改交付物

---

## 一、这个 Skill 解决什么问题

海外多市场销售的产品（如儿童电话手表），说明书需满足各国法规。过去靠人工逐份对照，存在：
- 审核颗粒度不统一（粗审/细审混用）
- 交付物不标准（报告/整改/数据索取各自为政）
- 高频错误反复出现（认证框架未置换、责任主体缺失、SAR 口径错误）
- 经验不可复用（新市场/新机型重新摸索）

本 Skill 将审核标准化为：**分级颗粒度 × MECE 审核对象 × 三件套交付物**。

---

## 二、触发方式

| 触发词 | 行为 |
|---|---|
| `/说明书细审` | L1-L9 全量 120 项（新设国家首次准入） |
| `/说明书粗审` | L4 说明书文本层 52 项（版本升级复核） |
| `/说明书` | 默认细审；先做信号判断（首次/升级、市场风险、变更范围），任一不确定则向用户确认后按回复定级 |

---

## 三、三件套交付物

每次审核**必须交付三样产物**：

| # | 交付物 | 格式 | 回答的问题 |
|---|---|---|---|
| ① | 审核清单的体检报告 | markdown / docx | 现状如何、哪里有问题 |
| ② | 说明书的整改清单 | excel · 16 列 · 每国一 sheet | 要改什么、依据什么 |
| ③ | 数据索取表 | excel · 按责任方 | 还缺什么数据、向谁要 |

**三件套联动**：体检报告（分析）→ 整改清单（执行动作）→ 数据索取表（收集证据），数据到位后回填报告完成该层判定。

### 整改清单 16 列

```
1-4  国家 / 说明书文件名称 / 说明书版本号 / 产品型号
5-7  检查项 / 状态 / 风险等级
8-9  说明书问题 / 整改落点（增/删/改在哪）
10   新增条款示例文案（三语：本地语/英文/中文）
11-12 援引法规 / 条款原文
13   备注
14   业务代表（执行人，输出时留空）
15   是否适用（下拉：适用 / 不适用 / 不适合）
16   整改结果（输出时留空）
```

色块约定：🟡黄底=需当地律师/语言专家确认；🔴红=高风险；🟠橙=中风险；🔵蓝=待确认

## 四、分级方法论

### 4.1 核心原则

1. **两源核验贯穿所有层**——一手信源（法规原文/MCP/PDF视觉）+ 间接信源（Notion/外网多源）交叉，未经交叉验证不得作为确定义务
2. **MECE 审核对象分层（L1-L9）**——按审核对象切分，互斥穷尽
3. **首次严格 / 升级粗审**——新设国家准入用最严格版，版本更新用粗审快检

### 4.2 MECE 审核对象分层（L1-L9，共 120 项）

| 层 | 审核对象 | 子类 / 项数 |
|---|---|---|
| L1 准入文件 | 认证与合规文件 | 5 子类 15 项 |
| L2 产品实物 | 硬件本体 | 5 子类 11 项 |
| L3 物理载体 | 设备与包装 | 4 子类 8 项 |
| L4 说明书文本 | 随附文档 | 12 子类 52 项 |
| L5 经营主体 | 责任实体 | 3 子类 6 项 |
| L6 软件数据 | App 与服务 | 4 子类 8 项 |
| L7 受众文化 | 市场接受度 | 3 子类 10 项（含宗教合规） |
| L8 市场宣称 | 营销面 | 2 子类 4 项 |
| L9 动态档案 | 时效与管理 | 3 子类 6 项 |

### 4.3 粗审 vs 细审

- **粗审 = L4 说明书文本层**（52 项）——四置换三载体在文本的落地 + 语言 + 失效信息
- **细审 = L1-L9 全量**（120 项）——粗审之上叠加证书/实物/载体/主体/数据/宗教/宣称/动态

### 4.4 方法论演进

本 Skill 由「四置换三载体两源核验」方法论迭代而来：两源核验保留贯穿，四置换三载体拆解融入 L1-L9 对象层（不再作为独立层级）。

---

## 五、使用流程

```
用户触发 → 分级判定（/细审 /粗审 /默认+确认）
  → 按审核清单逐项审核（两源核验）
  → 产出三件套交付物
  → 更新「市场×型号审核台账」（决定下次分级）
  → 整改落地 → 升级审核复核
```
